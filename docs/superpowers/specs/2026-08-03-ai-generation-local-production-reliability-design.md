# AI 生成本地与线上可靠性修复设计

## 背景

当前 AI 生成请求可以正常创建任务并写入 `pgmq` 队列，但应用服务器只等待 Worker 触发请求 1 秒。触发请求超时后，底层请求在本地开发运行时被终止，导致任务长期停留在 `queued`，前端只能持续轮询。

手动触发 Worker 时，队列可以正常读取并处理，说明队列、鉴权和 Worker 核心处理逻辑可用。Worker 继续执行后会在安全抓取阶段失败：Node 22 的 HTTPS 请求可能以 `all: true` 调用自定义 DNS `lookup`，现有实现仍返回单个地址参数，触发 `ERR_INVALID_IP_ADDRESS`，网关最终映射为 `502 CONTENT_BLOCKED`。

## 目标

- AI 创建接口继续快速返回 `202`，不等待网页抓取或 DeepSeek 完成。
- Worker 收到触发后快速确认，并在 Supabase Edge Runtime 后台可靠消费队列。
- 本地 Supabase 和线上 Supabase 使用同一套调度语义。
- 安全抓取网关兼容 Node 22 的普通 DNS lookup 和 `all: true` lookup。
- 保留现有每日 5 次限额、任务状态机、重试策略和前端轮询协议。

## 非目标

- 不改变页面设计、交互文案或数据库表结构。
- 不引入新的常驻服务、消息队列或定时任务平台。
- 不修改 DeepSeek 提示词、模型或思考模式配置。
- 不处理本轮验收发现的图片上传和移动端布局问题。

## 方案选择

采用方案 A：Worker 快速响应，并使用 Supabase Edge Runtime 的后台任务能力继续处理队列。

不采用独立常驻 Worker，因为它会增加部署单元和运维成本；不采用同步生成，因为它会让创建请求阻塞最长 120 秒并削弱现有异步任务架构。

## 架构与数据流

1. 用户提交资料链接。
2. 应用创建 AI 任务、扣减当日额度并写入 `pgmq`。
3. 应用调用 `ai-generation-worker`，最多等待 5 秒获取接单响应。
4. Worker 校验方法和 Bearer Token 后，将批处理 Promise 注册到 Edge Runtime 的后台任务调度器，并立即返回 `202`。
5. 后台任务读取最多 5 条消息，以并发度 2 执行现有 `runAiJob`。
6. 每条任务继续沿用现有状态机：认领、抓取、生成、完成或进入重试。
7. 前端沿用现有轮询节奏读取任务状态。

Worker 的后台调度器作为显式依赖注入到 handler：生产默认实现调用 `EdgeRuntime.waitUntil`，单元测试传入可控调度器并等待捕获的 Promise。这让“先响应、后完成”的行为可稳定验证。

## 安全网关兼容设计

DNS 仍只使用前置解析得到并验证过的公网地址，不改变 SSRF 防护边界。

- 当 Node 以普通 lookup 模式调用时，回调保持 `callback(null, address, family)`。
- 当 lookup options 包含 `all: true` 时，回调改为 `callback(null, [{ address, family }])`。
- HTTPS 的原始 `hostname`、`servername` 和 `Host` 继续保留，确保 TLS SNI 和证书校验仍针对原始域名。

## 错误处理

- Worker 鉴权失败和方法错误仍同步返回 `401`、`405`，不调度后台任务。
- Worker 接单成功返回 `202`；批处理内部继续统计并隔离单条消息失败。
- 后台任务顶层异常不得泄露原始错误正文，运行时日志保留稳定事件信息。
- 应用在 5 秒内未获得 Worker 接单响应时只记录告警，已创建任务和额度记录保持不变，便于后续补偿消费。
- 网关继续把底层网络异常映射为稳定、安全的错误码，不向用户暴露 IP 或底层堆栈。

## 测试设计

### Worker 回归测试

- 使用一个未完成的批处理 Promise。
- 调用 handler 后断言立即得到 `202`，且任务已交给调度器但尚未执行完。
- 释放批处理 Promise 后，断言队列消息被运行并正确删除或延迟。
- 保留鉴权、并发度、批量上限、畸形消息隔离测试。

### DNS 回归测试

- 现有普通 lookup 测试继续断言单地址和 family。
- 新增 `all: true` 测试，断言回调收到单元素地址数组。
- 运行真实本地网关请求，确认公开 HTTPS 页面由 `502` 恢复为 `200`。

### 端到端验证

- 重启安全网关和 Supabase Edge Functions。
- 创建一条新的 AI 任务。
- 确认任务自动离开 `queued`，无需手动触发 Worker。
- 确认安全网关成功抓取公开资料，并实际调用 `deepseek-v4-pro`。
- 确认生成结果进入可编辑草稿，用户仍需显式保存。

## 验收标准

- 创建接口在 Worker 接单后返回 `202`，不等待生成完成。
- 新任务在正常本地环境下 5 秒内至少进入 `fetching` 或后续状态。
- 网关对已验证的公开 HTTPS 地址返回成功，不再出现 `ERR_INVALID_IP_ADDRESS`。
- AI 任务在合理网络条件下 15 至 70 秒内完成或返回明确的终态错误。
- 新增回归测试、现有单元测试、集成测试、类型检查、Lint 和构建全部通过。
