# 知序 Aura · 本地演示

## 现场演示入口

打开 <http://127.0.0.1:4300/?demo=1&scenario=ai>，无需登录。

这是明确标注的预置样例，不读取输入链接、不调用模型。复用正式页面组件，支持操作、保存和刷新。修改保留在当前标签页，关闭标签页后不要依赖其继续保留。开始新一轮演示可点「重置示例」。

若服务已关闭，在项目根目录运行 `npm run demo`，保持终端打开。

## 建议演示顺序（约 5 分钟）

1. 点击「生成知识小结」，等待约 10 秒。介绍一篇文章如何变成核心主线与三个独立问题。
2. 点击「展开阅读」，在问题一点击「具体经历」，查看解释与原文依据。
3. 切到问题二，点击图中的「具体经历」，再点「查看完整解释」；通过「返回来源问题」回到原来的阅读位置。展示共享概念与局部结构图。
4. 收起阅读，在「用自己的话解释」写一句理解，点击「AI 润色」并采纳，保存修改；刷新页面，展示内容仍然保留。
5. 点击顶部「同主题串联」→「串联知识」。可以直接打开已保存的「从理解用户，到验证需求」，无需等待。
6. 要演示生成过程：点击「新增串联知识」，选择 9 月 22 日「用户访谈」、24 日「需求优先级」、26 日「原型测试」，输入问题后生成。
7. 点击图中的「需求假设」，展示 AI 补充原因；查看原始来源、概念关系和讲述提纲，再编辑一条概念解释并保存。
8. 可选：切到「多主题展示」，演示咖啡、宋词、徒步按原始记录展示，不强行连线。

日期随运行当天移动，跨天演示以顶部指南和日历实际日期为准。提炼与串联共用样例中的每日 5 次额度；「重置示例」可重新体验。

## 真实本地测试入口

页面：<http://127.0.0.1:3000>。数据库：本机 Supabase `127.0.0.1:54321`，项目 `supabase-web-v1`。

专用账号的邮箱、密码和恢复码保存在项目 `work/local-demo/account.json`，该目录被 Git 忽略。使用该账号登录。种子笔记明确标为「演示准备笔记」，不是模型生成结果。

已准备 9 月 22、24、26 日三组同主题 Agent 笔记，每组分别保存在手动和 AI 方式中：工具与外部知识、工作流与自主 Agent、评估与反馈循环。可以选择任一方式进入知识串联。

再次补齐演示笔记：`npm run demo:seed`。脚本只允许本地数据库与 3000 页面，不覆盖已保存的编辑，也不调用 AI。

服务启动命令（各自保持运行）：

```sh
# Docker Desktop 需运行；本地 Supabase 需已启动。
npm run dev -- --hostname 127.0.0.1 --port 3000
npm run dev:gateway
# 只有确认允许发送资料到 DeepSeek 后，才启用真实模型后台：
npm run dev:ai-worker
```

本轮准备时，本地数据库的两个待执行迁移已增量应用，未重置数据库。已有网关运行于 8788；勿重复启动占用同一端口的实例。真实后台未运行时，新生成任务不能完成；4300 样例入口可独立使用。

真实生成会将所提交的资料、提炼要求或所选笔记发送到项目配置的 DeepSeek 服务，会产生正常调用费用。真实模型、公开资料网站仍依赖网络。

知识串联可选问题：**如何从工具增强的模型，走向可控、可评估的 Agent 系统？**

真实提炼支持文字网页或公开 Markdown 链接，暂不支持视频/音频。真实请求可能等待数分钟。每日提炼和串联共享 5 次额度，建议用备用入口反复彩排。不要将预置结果解释为现场模型输出。
