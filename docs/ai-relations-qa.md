# AI 提炼：关系骨架规则与验收

## 可复用的提炼规则

新任务使用 `knowledge-relations-v2`。先回答“资料主要解释什么问题”，再识别节点角色与真实关系，最后安排阅读顺序。一篇资料可以混合多种内容类型，不强套单一模板。

| 内容类型 | 提炼重点 | 骨架表达 |
| --- | --- | --- |
| 概念与边界 | 定义、特征、适用范围、易混概念 | 分类、区别、条件 |
| 组成与分类 | 整体、部件、职责，区分组成与种类 | 包含、分类 |
| 运行机制与流程 | 输入、参与者、处理、判断、输出 | 流程、作用、反馈 |
| 原理与因果 | 前提、作用机制、结果 | 有依据的因果与依赖 |
| 问题与解决方案 | 约束、问题、机制、收益、代价 | 机制明确连接其作用对象 |
| 对比与选型 | 相同维度的差异与选择条件 | 对照、权衡、条件 |
| 方法与决策规则 | 前置条件、行动、检查、例外 | 条件、流程、反馈 |
| 观点与论证 | 主张、前提、证据、反例、局限 | 支持、依赖，标明作者观点 |
| 演化与历史 | 阶段、变化、驱动因素 | 演化，时间先后不等同于因果 |
| 案例与经验 | 背景、行动、观察、适用条件 | 例证连接所属概念，保留个案边界 |

所有关系必须能读成明确的命题：起点通过什么关系连接终点，成立条件是什么。不得使用“相关”“接下来”掩盖缺失的逻辑。机制、约束、组成和案例分别标明角色，独立主题允许不连线。

节点角色按概念本质判断：机制带来约束，仍归为机制；存放规则的组成部分影响行为，仍归为组成。对于会影响另一机制的操作，同时显示“操作作用于哪个对象”和“操作与另一机制如何权衡”两条关系。权衡的发生条件保留在边上，便于从任一端追踪。

组成与机制混合时，先保证核心部件可见：机制只修改整体中的特定部分，就让这部分成为关系端点，并显示它属于哪个整体。协议、格式、API 载体不能代替实际组成；不能把多个机制笼统地全部连接到整体。正文中的“通常、建议、也可以”等限定也须保留在关键辨析中，常见实现不能变成绝对属性。

节点和关系各自保留连续原文依据；引用必须能在实际抓取的正文中找到。引用存在只是必要条件，验收还需核对引用是否支持关系的方向、条件和含义。拒绝悬空节点、重名、组成环、虚构引用及会导致内容丢失的输出。

引用通常为 8–45 字，必要时可保留至 180 字符的完整条件句。无效引用的修正反馈提供最多两段从原文截取的附近片段，并继续标记为不可信资料；保存前仍需通过原文匹配。所有可检测的引用、长度和格式问题一次反馈。接近长度上限时，先去除表格的冗余格式空格，完整保留节点、关系、说明和条件。

引用已严格匹配时保留原样；仅有同类引号样式差异或额外末尾句号时，定位并取回原文的连续片段，再进行严格匹配。单引号与双引号不互换；改写词语、跳过编号、删去中间括注等仍判为无效，不通过补写伪造引文。

首次生成使用深度思考，输出预算为 16384 tokens。若结构、引用或长度校验失败，最多追加一次带字段级反馈的修正，直接输出完整 JSON；修正结果仍须通过同样的校验，不合格结果不会保存。两次请求共用原有超时信号，用量和调用次数累计记录。原有任务重试上限为三轮，因此任务最多调用模型六次。旧提示词版本维持原有行为。

修正轮关闭额外思考，为原文核对和完整 JSON 输出保留时间。参数依据：[DeepSeek 思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)。首次输出仍保留充足推理预算，最终小结仍受原有 5000 字符限制。

## 展示与编辑

- 显示核心问题、资料内容类型、节点角色和建议阅读顺序；明确阅读顺序不是执行或因果链。
- 将组成关系、作用与条件、运行与演化、比较与权衡分组展示；边上直接显示关系动词与必要条件。
- 点击节点阅读解释和原文依据，并聚焦相邻关系；点击关系另一端可继续追踪，点击“全部关系”恢复总览。
- 结构编译为可编辑的 Markdown 小结，保存、草稿和图形展示使用同一份内容。手工修改破坏结构，或加入尚不能被图形表达的边界说明时，显示完整文本，避免静默丢失信息。
- 旧记录保留原有阅读方式；新任务升级默认规则，不改写旧任务版本。个人理解继续由用户填写。
