# Task 5: Authentication API Routes And UI

## Implementation Summary

- Added a server-only Supabase `AuthPorts` adapter. It uses the admin client for user administration, private RPCs, and rate limiting, while the request-scoped SSR client performs sign-in/sign-out and session revalidation.
- Added shared, private/no-store JSON response mapping for validation, duplicate name, invalid credentials/recovery, rate limiting, unauthenticated access, and opaque server failures.
- Added registration, login, logout, recovery, recovery-code rotation, and profile routes. Profile rename revalidates the user, uses the immutable Auth UUID, requires the current password, and delegates to `updateProfile()`.
- Added warm-white/ink/green/coral auth pages, semantic forms, five accessible avatar radios, and the recovery-code dialog with user-triggered copy/download only. Recovery codes are never stored in browser persistence or URLs.
- Added an IPv4 bind to `test:integration` because Vinext accepts `--hostname` rather than Vite's `--host`; this permits its existing `127.0.0.1:3100` health check to run on this host.

## Security And Accessibility Self-Review

- Every JSON mutation validates before calling the adapter/service; failures use a uniform no-store response and expose neither raw database errors nor internal email, recovery digest, rate-limit bucket, or server secret.
- The adapter is server-only; the client bundle scan is clean. Recovery plaintext is returned only to the successful registration/recovery/rotation caller and only kept in component state until user action/close.
- SSR auth methods issue/clear Supabase cookies in the request context. `GET/PATCH /api/me` calls `auth.getUser()` before profile access; PATCH always uses the authenticated UUID and never accepts a UUID from input.
- Forms have labels, native password inputs, field-error alerts that retain values, five radio controls with accessible names, focus styles, compact stable controls, and responsive layouts. Dialog actions use lucide icons and named icon controls.

### Security And Accessibility Self-Review

- Rate-limit buckets ignore `X-Forwarded-For`; only non-empty normalized `CF-Connecting-IP` is used, with `local` fallback. Tests prove spoofed XFF cannot escape a verified-IP bucket and a distinct CF identity receives a distinct bucket.
- Every supplied profile identity field now requires `currentPassword`, signs in against the authenticated UUID/current login name through `updateProfile()`, and retains the immutable profile UUID. No route directly invokes the admin-backed profile identity mutation.
- Recovery now conditionally restores `next -> expected` after sign-in failure. Failed or throwing compensation surfaces `AggregateError("RECOVERY_ROLLBACK_FAILED")`; no recovery code is returned on either failure path.
- Dialog semantics include `aria-modal`, initial focus, Tab/Shift+Tab containment, Escape close, and restoration after close/unmount. Forms associate server `error.details.field` with invalid controls while generic errors remain available as alerts.

### Residual Concerns

- The integration runner temporarily replaces ignored `.dev.vars` to align with the active local Supabase stack, restoring it and resetting the database via an exit trap. A forced `SIGKILL` during that window can bypass the trap; the original local file should then be restored from the process backup or regenerated from `supabase status`.
- `npm run typecheck` remains blocked only by the pre-existing legacy Cloudflare type declarations noted above; this review-fix pass does not touch those files.
